# CLAUDE.md

Read [PLAN.md](PLAN.md) before working. Work phase by phase and tick a box only when its acceptance criteria pass.

## Hard rules (from PLAN.md section 2)

1. Synthetic data only. Never use real claims or real personal data. All PDFs are generated by this repo.
2. Never invent results. Every metric in the README must come from a real run saved under `reports/`.
3. TDD. Write the failing test first, then the code. Commit tests and code together in small commits.
4. Provider abstraction. All LLM calls go through one interface so a local model and Azure OpenAI can be swapped by config.
5. Local first, free. Development runs on a local model through Ollama. Cloud deployment is optional and last.
6. No em dashes in any file, commit message or README text. Use commas, colons or parentheses. A pre-commit hook enforces this.
7. Verify a library API in its current docs before using it. Pin versions in `pyproject.toml`.
8. Ask the user before spending money, signing up for cloud services, or changing the scope.

## Environment

- Windows 11, IDE is PyCharm. Python 3.13 in `.venv` (plain venv and pip).
- Local model: Ollama at `http://localhost:11434`, model `gemma4:e2b`, CPU only. Laptop has 16 GB RAM, so keep memory use modest.
- Unit tests use the fake provider and never touch the network.

## Commands

```
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m pytest
.venv\Scripts\python -m ruff check .
.venv\Scripts\python -m ruff format --check .
.venv\Scripts\pre-commit run --all-files
.venv\Scripts\python -m generator.build_golden   (regenerate data/golden, then commit it)
.venv\Scripts\python scripts\try_one_claim.py case_013   (manual run with the real model; Ollama must be running)
.venv\Scripts\python -m triage.cli path\to\claim.pdf [--json]   (triage any PDF)
.venv\Scripts\python -m pytest -m local_model   (optional end-to-end test with the real model)
```

## API

```
.venv\Scripts\python -m uvicorn triage.api.app:app --port 8000
```
Then http://127.0.0.1:8000/ (upload page) or /docs. The API key lives in .env (TRIAGE_API_KEYS,
never committed; .env.example shows the format). Never print the key in chat or logs.
Logs are JSON lines on stdout (triage logger); filter one request with
`findstr <request_id>`. GET /v1/metrics (with key) shows counts, error rate and latency.
Never log document text, field values that may hold PII, or restored summaries.

## Docker and CI

```
docker compose up --build          (API + Ollama + one-time model pull; http://127.0.0.1:8000/)
docker build -t claim-triage-agent .
```
CI (.github/workflows/ci.yml): lint, pytest, an evaluation of ten dev cases replayed from
evals/cassettes/ci_subset.json (TRIAGE_LLM_PROVIDER=replay), and a Docker build.
After changing a prompt, the redaction or a schema, re-record the cassette with the real model:
`python -m evals.run_eval --cases <the ten CI_CASES in ci.yml> --label ci-cassette --record evals\cassettes\ci_subset.json`

## Evaluation workflow

```
.venv\Scripts\python -m evals.run_eval --split dev --label <name>   (about 15 min on this laptop)
.venv\Scripts\python -m evals.regression                              (compare with the previous dev run)
```

Tune on dev only. Holdout ran once for the Phase 4 milestone; run it again only at the next milestone.
Bump the version line in a prompt file whenever its text changes. Current results: docs/model_card.md.

Routing thresholds live in `config/routing.yaml`; the rule order is in `docs/routing_policy.md`.
